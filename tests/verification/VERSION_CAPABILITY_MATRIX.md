## Scalar conversion boundary

Converters with `ConvertsNulls=true` are rejected during model validation. The provider preserves null as an absent graph property and does not implement EF's experimental null-to-sentinel conversion contract. Node and identified-edge payload regressions verify rejection before driver access; ordinary null-preserving explicit converters retain the behavior below.

| CLR value | Store policy | Verified evidence / limitation |
|---|---|---|
| `string`, `bool`, `double` | Native scalar values | Binding tests and live materialization; nullable variants exercised. String ordering follows Neo4j; culture equivalence and special floating-point values are not established. |
| `int`, `long` | Integer values; `int` writes as `long`, reads use checked narrowing | Unit and live tests, including out-of-range `int` rejection. Unconverted `long` generated concurrency versions also have live save evidence. |
| `Guid` | Canonical `D` string; exact-format parsing | Unit and live reads/writes and endpoint identity. No native UUID mapping. |
| Enum | Checked signed `long` representation | Unit and live materialization/parameter comparisons; overflow and underlying-type range rejection have unit coverage. |
| Nullable / required properties | Null remains null where allowed; required nulls reject; written null removes a property | Unit and live decoding/mutation cases. Complete row decoding precedes EF materialization. |
| `decimal`, `DateTime` and other temporal values with explicit converters | Invariant decimal string; DateTime binary `long`; explicit reversible representations for other fixture values | The selected upstream fixture writes converted values and its original asserters validate all returned ordinary-entity scalars in **12 live facts**. Organization additionally round-trips required/nullable DateOnly ISO strings in identified-edge payloads. These results establish those representations, not native temporal/decimal operators or every possible custom converter; see the [fixture contract](../GraphBridge.SpecificationTests/README.md). |
| Other scalar/collection/structured types | No default mapping beyond the supported scalar set | Unsupported mappings reject; arbitrary custom converter semantics are not generally certified. |

Schema evidence: [M5 live tests](../GraphBridge.IntegrationTests/ProviderSchemaTests.cs) and [ADR-0017](../../docs/architecture/adr/ADR-0017.md). Inspection distinguishes database existence/type enforcement from provider checks and does not validate stored graph data. Node alternate-key requirements and ordered index intent are represented; normal runtime guards retain their primary-key/edge-ID scope, and schema deployment remains explicit.

Explicit converters support value conversion; they do not establish ordering equivalence. Converted range/order operations, including inherited endpoint converters, reject. PK/FK conversions must preserve model values when written and reproduce the exact stored representation when read. Default Guid keys require lowercase canonical `D` strings. Lossy key conversions and resolved key comparers differing from the type mapping's comparer reject. These shared identity guards pass the M4 unit/live regression.

The native Cypher lane supports explicit DTO/path projectors and transaction sharing with untracked results; it does not extend LINQ translation or refresh tracked values. The [README support boundary](../../README.md), [association ADR](../../docs/architecture/adr/ADR-0015.md) and [identified/native ADR](../../docs/architecture/adr/ADR-0016.md) describe supported query and storage shapes.
