# Allocation investigation

Historical allocation reports are maintained separately. For a collected process report, run `python eng/profiling/Compare-Allocations.py PATH_TO_RUNS_JSON` to reproduce process-level 95% intervals. Run `python eng/profiling/test_compare_allocations.py` to check the t critical value, independent process aggregation and invalid-evidence rejection.

The focused benchmark reuses the original 100,000-node seed, full-entity direct/provider read and correctness assertions. It has a separate completion contract and never claims the full benchmark matrix passed. `Run-Benchmarks.ps1 -AllocationBackend driver|ef -Sizes 100000 -EdgeSizes 1 -Writes 1` runs it under the existing resource/ownership supervisor. Edge/write sizes are required placeholders and are not executed.

Use `-TraceToolPath /path/to/dotnet-trace` to launch the same process under pinned `dotnet-trace` **9.0.661903**, `gc-verbose`, a 128 MiB event buffer, and the `GraphBridge-AllocationProfile` marker provider. First-observed and warmup work remain outside report windows. Keep untraced and traced runs separate: tracing perturbs allocations/timing. The runner records the actual binary hash, dirty state and memory timeline and retains the trace alongside data. It never changes or stops foreign resources.

`AllocationReport.cs` is an optional standalone analysis program requiring `Microsoft.Diagnostics.Tracing.TraceEvent` **3.2.6**. Run `pwsh eng/profiling/Export-AllocationReport.ps1 -TracePath TRACE.nettrace -OutputDirectory NEW_DIRECTORY` to build it in an isolated artifact project and analyze under the 5 GiB supervisor. The analysis dependency lock is retained with the report; it is not a provider dependency. It uses [TraceLog's EventPipe conversion](https://github.com/microsoft/perfview/blob/v3.2.6/src/TraceEvent/TraceLog.cs), rejects missing windows/allocations or reported lost events, and produces JSON, the five largest complete allocation stacks, and a Speedscope allocation flamegraph. No CPU-sample weights are mislabeled as allocation bytes.

Weights are allocation-tick estimates across all threads in a warm measurement window, not exact object/type totals. Inclusive method weights overlap. Missing/unresolved frames are retained visibly. The trace contains synthetic benchmark activity and method/type metadata; do not apply this workflow to production data and publish raw traces without review. Raw trace and converted ETLX remain ignored artifacts; the profiler and analysis dependency are not shipped in GraphBridge runtime packages.
